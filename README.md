# SimpliiGood Creator Club — גרסה 0.2

מערכת הדגמה אינטראקטיבית לניהול קהילת יוצרים ושגרירים בישראל ובארה״ב.
נוצרה ב־5 בספטמבר 2026. גרסה 0.2 מוסיפה דחיית מועמדים, עריכה וארכוב של משימות.

## פתיחה

פתחו את `index.html` בדפדפן במחשב. הקובץ עצמאי; אין צורך בהתקנה, בשרת או במפתח API.
אפשר גם לפתוח את הקובץ `START_WINDOWS.bat` לאחר חילוץ כל התיקייה.

הממשק מתחיל בעברית. הכפתור EN מחליף לאנגלית, ו־HE מחזיר לעברית.
אפשר לעבור בין ״מנהל התוכנית״ ל״פורטל יוצרים״ בחלק העליון.

## חשוב

זו **סביבת הדגמה מקומית**, לא שירות שהושק אונליין.

- כל הפרופילים, נתוני הקהל, המחירים, המשימות והתוכן ההתחלתי בדיוניים.
- הנתונים נשמרים בדפדפן בלבד, ככל שהדפדפן מתיר שמירה מקומית. אין סנכרון בין מכשירים.
- אין חשבונות מאובטחים, הרשאות שרת או מסד נתונים משותף.
- החלפת מצב מנהל/יוצר היא תצוגת הדגמה, לא מערכת התחברות.
- אין שליחת אימיילים, הודעות, תשלומים, פרסום ברשתות או חיבור ל־AI.
- הגשת תוכן נעשית באמצעות קישור בלבד; אין העלאת קבצים או אחסון וידאו.
- ״נתונים נבדקו״ ו״פרסום אומת״ הם סימונים ידניים בהדגמה, לא אימות באמצעות הרשתות.
- ״רישום תשלום״ אינו מעביר כסף ואינו מהווה מסמך חשבונאי.
- אין להזין פרטי יוצרים אמיתיים, פרטי בנק, סיסמאות, מפתחות API או תוכן סודי.
- המחירים והנחות השימוש בתוכן הם דוגמאות עבודה, לא מחירון מומלץ ולא הסכם משפטי.

## מסלול הבדיקה המהיר

1. בחלק העליון, עברו ל״פורטל יוצרים״. היוצרת Maya Moves / Demo נבחרת כברירת מחדל.
2. פתחו את ההצעה למשימה From freezer to smoothie, אשרו שקראתם וקבלו אותה.
3. פתחו שוב את העבודה והגישו קישור לדוגמה: `https://example.com/demo-draft`.
4. חזרו למנהל התוכנית > תוכן לאישור. פתחו את העבודה, סמנו את ארבע הבדיקות ואשרו.
5. עברו שוב ליוצרת ודווחו על פרסום באמצעות `https://example.com/demo-post`.
6. חזרו לתוכן לאישור, אמתו ידנית את הפרסום.
7. במסך התשלומים אפשר לרשום תשלום לדוגמה עם אסמכתה כגון `DEMO-001`.

קישורי example.com הם מצייני מקום. אין בהם תוכן אמיתי לבדיקה.
התהליך הזה נועד לבדיקת הממשק בלבד.

## מה אפשר לעשות

### מנהל התוכנית
- סקירה של יוצרים פעילים, תוכן לבדיקה, התחייבויות ותקציב פנוי.
- סינון בין ישראל לארה״ב; אין חיבור בין סכומי ILS ו־USD.
- צפייה בפרופילים, אישור או דחייה של מועמדים (עם סיבה), וסימון בדיקה ידנית של נתוני קהל.
- יצירת משימות עם שוק, פורמט, יעד, תקציב, מספר מקומות ומועד.
- עריכת משימה קיימת. השוק והמטבע נעולים; הפורמט נעול אחרי שיש שיבוצים; התקציב ומספר המקומות
  לא יכולים לרדת מתחת למה שכבר הוקצה.
- העברת משימה לארכיון כשאין בה עבודות פתוחות. משימה בארכיון מוסתרת מיוצרים וסגורה להצעות,
  והנתונים הכספיים שלה נשמרים. אפשר לשחזר אותה בכל עת.
- יצירת הצעות אישיות ושמירת תקציב עבורן.
- אישור תוכן, בקשת תיקונים ואימות פרסום.
- רישום תשלום לדוגמה וייצוא CSV של רשומות התשלום.
- שינוי תעריפי ההדגמה להצעות חדשות בלבד.
- ייצוא וייבוא גיבוי JSON, ואיפוס הנתונים.

### פורטל יוצרים
- בחירת פרופיל דוגמה.
- צפייה בהצעות ובמשימות של הפרופיל שנבחר.
- קבלה או דחייה של הצעה.
- הגשת תוכן, צפייה במשוב והגשת גרסה מתוקנת.
- דיווח על פרסום רק אחרי אישור תוכן.
- צפייה בסטטוסים ובתגמול שהוגדר.

### טופס מועמדות
- פרטי דוגמה על היוצר, תחום התוכן, הערוץ, גודל הקהל והמעורבות.
- המועמדות נשמרת מקומית ומתחילה בסטטוס ממתין לבדיקה.
- אין שליחה לחברה ואין יצירת חשבון אמיתי.

## תמחור ותקציב

תחשיב ההצעה הראשוני:
עלות יצירה לפי פורמט + תעריף פרסום לפי מדרגת עוקבים × מקדם מעורבות × שיעור קהל בשוק היעד.
התוצאה של רכיב הפרסום מעוגלת ל־5 הקרובים. לבלוגים וניוזלטרים אין תמחור פרסום אוטומטי לפי עוקבים;
יש להזין את הרכיב ידנית.

המנהל יכול לערוך כל רכיב לפני יצירת ההצעה. לאחר יצירתה, המחיר נשמר ואינו משתנה עם המחירון.
שדה הבונוס הוא הצעת אחוז בלבד. ייחוס מכירות וחישוב או תשלום בונוסים **אינם ממומשים**.

תקציב משימה כולל בהדגמה תגמולי יוצרים בלבד. הוא אינו כולל מוצר, משלוח קפוא, מסים,
עמלות ספק, תוכנה או זמן ניהול. לפני פיילוט מסחרי יש להוסיף אותם לתקציב הכולל.

## שמירת נתונים

בהגדרות אפשר לייצא גיבוי JSON. מומלץ לייצא לפני החלפת קובץ או מחיקת נתוני דפדפן.
מיקום הקובץ, דפדפן אחר, מצב פרטי או חסימת אחסון עשויים להשפיע על זמינות הנתונים.
האבטיפוס אינו מונע לחלוטין דריסת נתונים בשימוש בו־זמני; הוא מיועד להדגמה במכשיר אחד.

אם הדפדפן חוסם פתיחה מקומית או שמירה, אפשר להשתמש בשרת מקומי אופציונלי:
```bash
python serve.py
```
השרת מאזין רק ל־127.0.0.1:8765. גם במצב הזה הנתונים נשמרים בדפדפן, לא בשרת.
אין לחשוף אותו לאינטרנט.

## קבצי המקור

- `index.html` — המערכת כקובץ עצמאי.
- `core.js` — חוקים עסקיים ומכונת מצבים; ללא DOM, נבדק ב־Node.
- `format.js` — פונקציות עיצוב טהורות (escaping, מטבע, תאריכים, CSV); ללא DOM, נבדק ב־Node.
- `app/` — הממשק, קובץ לכל מסך: `00-state.js` (מצב משותף), `10-ui.js` (רכיבים), `20-shell.js` (מעטפת וניווט),
  `30-dashboard.js`, `31-missions.js`, `32-creators.js`, `33-review.js`, `34-payments.js`,
  `35-creator-portal.js`, `36-settings.js`, `90-events.js` (אירועים והפעלה). הבנייה מאחדת אותם לפי סדר השם.
- `styles.css` — עיצוב מותאם למסך מחשב ומובייל, עברית ואנגלית.
- `i18n.json` — טקסטי הממשק.
- `build.py` — בנייה מחדש של index.html, ללא תלויות נוספות. `--check` מוודא שהקובץ מעודכן.
- `serve.py` — שרת מקומי אופציונלי (127.0.0.1 בלבד).
- `START_WINDOWS.bat` — פתיחת index.html בווינדוס.
- `test_core.js` — בדיקות כללי המערכת.
- `test_format.js` — בדיקות יחידה לפונקציות העיצוב.
- `test_ui.py` — בדיקות דפדפן; Playwright דרוש לבדיקות בלבד.
- `PRODUCT_SPEC.md` — היקף הגרסה והעבודה הנדרשת לשירות אמיתי.
- `TEST_RESULTS.md` — מה נבדק ומה טרם אומת.

לא נכללים קובצי פונטים או נכסי אריזה. הטקסט SimpliiGood בכותרת הוא ייצוג טיפוגרפי לאבטיפוס,
לא קובץ הלוגו הרשמי.

## בנייה ובדיקות למפתח

```bash
python build.py
node test_core.js
node test_format.js
python test_ui.py
```

עורכים קבצים ב־`core.js`, `format.js`, `app/`, `styles.css` או `i18n.json`, ואז מריצים `python build.py`.
אין לערוך את `index.html` ידנית.

בדיקות הדפדפן מרימות שרת מקומי זמני על 127.0.0.1 ורצות ב־Chromium אמיתי עם אחסון דפדפן אמיתי,
לאורך כל מסלול הבדיקה המהיר שלמעלה. Playwright נדרש לבדיקות בלבד:
```bash
pip install playwright && python -m playwright install chromium
```
ארבע הפקודות רצות אוטומטית ב־GitHub Actions בכל דחיפה (`.github/workflows/ci.yml`).
ה־CI נכשל אם `index.html` לא נבנה מחדש אחרי שינוי בקבצי המקור.
עדיין מומלץ לבצע בדיקת קבלה במחשב המשתמש, במיוחד פתיחה מקובץ בווינדוס.
